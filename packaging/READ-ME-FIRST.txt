EXPERIMENTAL BUILD: EARLIER-PASS VRS (0.1.1-early.3)

Back up your old DLLs and INI before installing. Keep this test launcher too.
In the root INI, under [Experimental], set EarlyPasses=true and restart.
Allow 10 seconds in your scene. Compare against EarlyPasses=false with the same
sizes, resolution, Turbo and scissor settings; keep debug outlines off.
Old on/off values still work; use true/false for normal editing.
EarlyPasses=trace learns candidates without widening VRS (tracking overhead test).
The default is off. A confirmed FPS improvement is not promised.

This build reduces tracking overhead and reuses up to 64 idle VRS framebuffers.
Reuse is active in false/trace/true; early-pass inference defaults to false.
M8.34 reports framebuffer reuse and sampled CPU overhead (not GPU timings).

With Logging Level=info, look in %TEMP%\BeamNG_VRS_layer.log for M8.33 EARLY_VRS.
Both selected and binds must increase to confirm additional recorded VRS coverage.
If they stay zero, send that log: this narrow experiment did not find a usable path.
Check both eyes for flicker/incorrect shading. Restore off if anything is worse.
For full instructions, see docs/EARLY-VRS-TEST.md on the experiment/early-vrs branch.

BeamNG-VRS 0.1.0 - portable Windows x64

INSTALL
1. Close BeamNG.
2. Extract this entire ZIP into the BeamNG installation root (beside Bin64).
   Extraction directly inside Bin64 also works.
   Keep the BeamNG-VRS folder and Launch-BeamNG-VRS.cmd together.
3. Edit BeamNG-VRS.ini beside Launch-BeamNG-VRS.cmd in Notepad if desired.
4. Start Launch-BeamNG-VRS.cmd. It launches BeamNG in Vulkan mode.
5. Enable VR in BeamNG as usual. Restart the game after every settings change.

SETTINGS
Open BeamNG-VRS/VRS-SETTINGS.png for a visual explanation.
[Foveation] Enabled=false disables VRS while leaving scissor/turbo available.
The default Shape=circle uses diameters relative to eye-image height.
Size1x1=0.25 sets the sharp circle's diameter to 25% of eye height.
Size2x2=0.60 sets the medium-quality region's outer diameter to 60%.
Size2x2 must be at least Size1x1. Larger sizes preserve more detail.
Shape can be circle, square or ellipse. Circle uses height-relative diameter;
square uses height-relative side length.
DrawOutline=true shows region borders. Leave it false for gameplay.
If VRS shimmers, try BeamNG's MSAA setting; performance cost varies by setup.
You can also disable Foveation and keep Scissor enabled for cropping alone.
Under [Scissor], Enabled=true activates experimental cropping. Top and Bottom
are fractions of eye-image height: 0.30 crops 30% from that edge (range 0-0.49).
Horizontal edges use each eye's image width, with four separate controls:
LeftEyeLeft  = left eye, outside
LeftEyeRight = left eye, near the nose
RightEyeLeft = right eye, near the nose
RightEyeRight= right eye, outside
Outer edges default to 0.10 (10%); nose-side edges default to 0.
Each accepts 0 to 0.49. Start small and check each eye.
For outside-only cropping, try LeftEyeLeft=0.05 and RightEyeRight=0.05;
keep LeftEyeRight=0 and RightEyeLeft=0 to leave the nose-side edges untouched.
Old shared Left/Right settings remain accepted. Explicit per-eye keys override
those edges independently. Update the launcher and both DLLs together.
Leave scissor disabled unless you have tested visible edges and performance.
[Performance] TurboMode=true enables experimental frame-wait overlap; default
true. Restart after changes. It can interfere with motion reprojection. Compare
headset smoothness and frame times; set false if it worsens pacing or appearance.
[Logging] Level accepts off, errors, info (default) or debug. Use off to stop
layer log output; Diagnose-BeamNG-VRS.cmd overrides it with debug logging.
GracePeriodMs=30 holds the last valid gaze briefly; 0 disables that grace.
GazeRefreshMs=8 sets the CPU gaze polling interval. It is not display latency.
Valid eye tracking follows gaze; unavailable tracking uses fixed center.
Use a dot in decimal numbers. Comments must be on separate lines.
The launcher reports malformed settings and refuses to start the game.
Direct layer loading disables activation for invalid INI files and reports
the error to a debugger. The public launcher clears old project settings in
the child process so the INI applies consistently; developer scripts that load
the layers directly can still use environment overrides.

REQUIREMENTS AND LIMITATIONS
Windows x64, BeamNG in Vulkan VR mode, an OpenXR runtime, and a GPU/driver
supporting attachment fragment shading rate. No universal headset support or
FPS gain is promised. Test builds can cause crashes or rendering artifacts.
The launcher uses Windows PowerShell 5.1, included by default in Windows 10
and 11; PowerShell 7 is not needed. The launcher validates the INI itself;
the package contains no EXE files.
No administrator rights, registry registration or original game-file edits.
The game may require its normal Steam session. Start Steam first if needed.

UNINSTALL / UPDATE
Launch BeamNG normally to stop using these layers. To uninstall, close the
game, then delete BeamNG-VRS.ini, Launch-BeamNG-VRS.cmd, Diagnose-BeamNG-VRS.cmd and the
BeamNG-VRS folder.
Back up your INI before extracting an update: extraction can overwrite it.
When updating from an earlier beta, delete the old BeamNG-VRS-Check.exe;
it is no longer used. Restore your INI after updating to keep your settings.
Beta.8 moves the INI to the extraction root, beside the launch CMD. Restore
an earlier beta's saved INI here instead of inside BeamNG-VRS.

TROUBLESHOOTING
Previous betas can fail with "./BeamNG_VRS.dll" and Windows error 87.
This package fixes the Windows relative paths in both loader manifests.
If normal Vulkan works but VRS launch reports no rendering device, run
Diagnose-BeamNG-VRS.cmd. Close the game and any error dialog, then inspect
the loader log at the path printed in the window. Run with your normal user
account: Vulkan ignores custom layer search paths in elevated applications.
The launcher preserves normal Vulkan layer discovery and existing overrides.
Extract into the game installation folder, not its user-data folder.
For an unusual layout, run BeamNG-VRS/Launch-BeamNG-VRS.ps1 with
-GameExecutable "C:\path\to\Bin64\BeamNG.drive.x64.exe".
Logs are in the Windows temporary folder; review/redact them before sharing.
This package is unsigned. Build information and SHA256SUMS.txt are included.
